Backend ROSA

Soạn JavaScript, lưu nháp vào database thiết bị, kiểm tra và chạy thử. Phát hành tạo phiên bản dùng cho trang IoT/API; sửa bản nháp không đổi phiên bản đang chạy.

Bắt đầu

  1. Mở menu thiết bị → Backend, hoặc /backend và kết nối IOID@API key thiết bị.
  2. Đặt tên như kiem-tra-ton-kho. Mỗi IOID có không gian tên riêng.
  3. Viết export default async function main(input, rosa). Chọn Ví dụ để chèn mẫu.
  4. Khai báo quyền SDK, schema input/output và SyncID trả phí.
  5. Kiểm tra Cú pháp, Phân tích tĩnh; nhập Input JSON và chạy thử.
  6. Phát hành để trang IoT/API gọi được. Nút Tắt dừng nhận lượt mới.

Chạy thật trên ROSA có thể ghi database/điều khiển thiết bị và tính phí. Simulator dùng V8 thật, SQLite và thiết bị mô phỏng; chi phí hiển thị chỉ là mô phỏng.

SDK

Lệnh Kết quả / quyền
await rosa.db.macro('stock-find', {sku:input.sku}) Mảng dòng, quyền macros. SQL nằm trong system_macros; dùng :sku.
await rosa.db.report('stock-report', {}) Mảng dòng từ DuckDB, quyền reports. Một SELECT/WITH; snapshot tối đa 100.000 dòng / 16 MiB.
await rosa.iot.latest('device') Trạng thái mới nhất của các fields được cấp quyền.
await rosa.iot.timeseries('device', {from:Date.now()-3600000,to:Date.now()}) Lịch sử, khoảng thời gian tối đa 31 ngày.
await rosa.iot.command('device', 'switch', {state:'ON'}) Gửi lệnh system_cmds được cấp quyền; accepted là gateway nhận yêu cầu. 
{
  "macros": ["stock-find"], "reports": ["stock-report"],
  "devices": {"device": {"ioid":"self", "read":true,
    "fields":["temperature","O101"], "commands":["switch"]}}
}

self là IOID chứa backend. Với IOID khác, xác minh credential trong ô thiết bị khác. Credential không được đưa vào isolate. Lệnh dùng placeholder <<state>>; không dùng các lệnh yêu cầu danh tính hoặc page_only từ backend.

Gọi từ trang IoT

Trong system_pages.meta, thêm {"publicApi":{"backends":["kiem-tra-ton-kho"]}}. Backend phải được phát hành; không cần bật truy cập ngoài. 

const result = await rosa.backend.run('kiem-tra-ton-kho', {sku:'SP001'});

SDK được ROSA/Simulator tự chèn vào trang. Browser không nhận API key, SyncID trả phí hoặc địa chỉ runner. Khi lỗi mạng, giữ error.requestId và dùng lại trong tùy chọn {requestId} để kiểm tra lượt cũ thay vì lặp tác động.

API ngoài

Bật Truy cập từ ngoài, chọn Bearer, X-API-Key hoặc Basic, tạo khóa và lưu cấu hình. URL: /bw/IO282xxxx/ten-backend. Với Basic, dùng username đã đặt và API key làm password. Khóa chỉ lưu dạng hash. 

curl -X POST 'https://rosa.technology/bw/IO282xxxx/kiem-tra-ton-kho' \
 -H 'Authorization: Bearer YOUR_API_KEY' \
 -H 'Content-Type: application/json' -H 'Idempotency-Key: order-0001' \
 -d '{"sku":"SP001"}'
# HTTP 202: lưu runId; GET cùng URL với ?runId=... và cùng xác thực.

Lịch sử và Idempotency-Key được giữ 7 ngày. Dùng lại Idempotency-Key cho cùng yêu cầu sau lỗi mạng trong thời gian này. Đổi input với cùng key trả 409. Không tự gửi lại lệnh thiết bị khi trạng thái báo không chắc chắn.

Giới hạn và phí

Timeout mặc định 180 giây gồm cả thời gian chờ, đặt trong /manage. CPU time của isolate được tính riêng với phí macro/lệnh, trừ vào SyncID của backend. Chờ database/IoT không tính thành CPU. Mặc định V8 memory limit 10 MiB; đây là giới hạn heap của V8, có thể vượt tạm thời. Production bổ sung giới hạn RAM/CPU cứng cho từng pool container.

Không có require/import, filesystem, npm hoặc HTTP tùy ý. Output tối đa 256 KiB, input 64 KiB; tối đa 1.000 lời gọi SDK và 16 lời gọi đang chờ mỗi lượt. SQLite chờ khóa theo deadline. Timeout hoàn tác transaction chưa commit, không hoàn tác những macro/lệnh đã hoàn tất trước đó.

Chạy định kỳ và mô phỏng lịch

Phát hành backend nhận input {}, bật Định kỳ, chọn số nguyên giờ rồi Lưu lịch. Chu kỳ tối thiểu và hạn mức 100 backend/thiết bị nằm trong /manage. Cờ định kỳ không mở API ngoài.

Job đến hạn chờ trong SQLite, chưa có isolate hoặc phí. Lượt gọi trực tiếp được ưu tiên; lịch dùng tối đa 20% trần đồng thời toàn server. SyncID hết tiền thì bỏ kỳ; job lỗi không retry. Kỳ tiếp theo vẫn được xét. Lần đầu là mốc giờ sau đủ chu kỳ, các kỳ lỡ không chạy bù hàng loạt.
